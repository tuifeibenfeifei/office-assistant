# 全能办公助手 · 架构设计

> 本文档说明系统的分层、模块职责与关键设计决策，并逐条对应《全能办公助手插件_功能说明》
> 与《项目计划书》的要求。所有"如实说明"的部分都明确标注了边界。

---

## 一、技术选型与理由

| 方案 | 常驻内存 | 系统 API 能力 | 本次可用性 | 结论 |
| --- | --- | --- | --- | --- |
| Electron + Vue/React | 200–400 MB | 需原生模块 | — | 与功能四目标冲突，不采用 |
| Tauri 2.x + Rust + React | 50–120 MB | 最强 | **不可用**：本机无 Rust 工具链，NuGet/crates 网络不可达 | 文档推荐项，但当前环境无法产出可运行程序 |
| **C# WPF / .NET 8** | 80–150 MB | 很强（回收站、文件操作、P/Invoke） | **可用**：SDK 与 WindowsDesktop 运行时齐备 | **本次采用**（《功能说明》三·技术选型明确列为备选） |

在选定 WPF 之后，进一步选择**零第三方 NuGet 依赖**，用系统自带能力替代常用包：

| 常见做法 | 本项目做法 | 理由 |
| --- | --- | --- |
| Microsoft.Data.Sqlite / SQLitePCLRaw | P/Invoke 系统 `winsqlite3.dll` | 离线可构建；系统组件随更新维护 |
| `System.Security.Cryptography.ProtectedData` 包 | P/Invoke `crypt32.dll` 的 `CryptProtectData` | 同一套 Windows DPAPI，少一个包 |
| `Microsoft.VisualBasic.FileIO` 或第三方回收站库 | COM `IFileOperation` + `SHFileOperation` 回退 | 支持长路径、可静默执行、语义明确 |
| Newtonsoft.Json / System.Text.Json 反射 | `System.Text.Json` 源生成上下文 | 无反射、兼容裁剪、启动更快 |
| xUnit / NUnit / MSTest | 自研控制台测试宿主 | 无需联网取包；用例可读性可控 |
| 外部 .ico 资源 | GDI+ 运行时生成图标（含角标） | 无二进制资源、便于审查 |

程序集只有两个（`OfficeAssistant.Core.dll`、`全能办公助手.dll`），便携版约 1 MB。

## 二、分层结构

```
┌──────────────────────────────────────────────────────────────┐
│ 用户界面层  WPF (.NET 8)                                      │
│  MainWindow：五个功能页签 + 状态栏 + 托盘；拖拽层；对话框服务    │
│  ViewModels：NetworkPage / HomeworkPage / DiskPage /          │
│              ResourcePage / SettingsPage / Main              │
├──────────────────────────────────────────────────────────────┤
│ 桥接层（进程内强类型边界）                                      │
│  AppHost：唯一装配点，持有数据库与全部引擎                       │
│  OperationExecutor：删除/移动/重命名的唯一入口（白名单校验）       │
│  Dialogs / TrayService：界面能力注入，页面不直接调用 MessageBox   │
├──────────────────────────────────────────────────────────────┤
│ 核心服务层（OfficeAssistant.Core，与 UI 技术无关）              │
│  ScanEngine          文件扫描引擎（并行首扫 + 指纹增量）          │
│  RecognitionEngine   内容识别引擎（双通道判定 + 摘要/缩略图/元信息）│
│  ProtectionEngine    误删防护引擎（白名单 + 三级风险）            │
│  CleanupEngine       清理规则与一键清理引擎                      │
│  ResourceOptimizer   工作集压缩 / 优先级 / 报告                  │
│  ResourceScheduler   类 cron 调度 + 阈值触发                     │
│  ProbeService        连通性测速（DNS/TCP/HTTPS）                 │
│  GitConfigEngine     配置快照 / 应用 / 一键还原                   │
│  HomeworkService     适配器抽象 / 凭据 / 同步 / 提醒             │
│  ComplianceAudit     合规红线回归审计                            │
├──────────────────────────────────────────────────────────────┤
│ 系统接口层                                                     │
│  Win32：FindFirstFileExW、EmptyWorkingSet、SetPriorityClass、    │
│         NtQuerySystemInformation、GetLastInputInfo             │
│  Shell：IFileOperation、SHCreateItemFromParsingName、            │
│         SHFileOperation（回退）                                 │
│  加密：crypt32 DPAPI                                          │
│  存储：winsqlite3.dll（SQLite）                                 │
│  网络：HttpClient / TcpClient / Dns / netsh（只读查询）           │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**：界面层 → 桥接层 → 核心服务层 → 系统接口层。
核心服务层不引用 `System.Windows.*`（仅在识别引擎中引用 `System.Drawing.Common` 生成缩略图），
因此引擎可被控制台测试宿主直接驱动，这也是自测能在无界面环境跑通的原因。

## 三、模块职责与关键实现

### 3.1 AppHost（装配与生命周期）

- 定位数据目录（`%LOCALAPPDATA%\全能办公助手`，或便携模式 `程序目录\data`，或环境变量
  `OFFICEASSISTANT_DATA_DIR` 覆盖——最后一项用于自动化测试隔离）。
- 打开 SQLite、建表、写入默认清理规则与类型规则表。
- 启动后台服务：资源管家调度器、学习通自动同步（均可在设置中关闭）。
- 提供 `IsElevated`、`RunComplianceAudit()` 等横切能力。

### 3.2 Data 层（SQLite 访问）

- `SqliteNative`：`winsqlite3.dll` 的 P/Invoke 声明。
  **刻意不绑定 `sqlite3_exec`**——实测本机该函数会触发 `STATUS_STACK_BUFFER_OVERRUN (0xC0000409)`
  终止进程，而 `prepare/step/finalize` 通道完全正常，因此 `Exec` 由逐条 `prepare + step` 实现
  （按分号切分，忽略行注释）。
- `SqliteStatement`：位置参数绑定。**所有文本/二进制都以 `SQLITE_TRANSIENT` 绑定**——
  用 `SQLITE_STATIC` 会让 SQLite 不复制内容，而调用方随后立即释放缓冲区，
  语句再 `step` 时读到悬垂内存，表现为读回文本错乱（该缺陷由自测捕获：`a.txt` → `\n txt`）。
- 事务：磁盘库的 `BEGIN/COMMIT` 是全局的，用进程内锁保证同一时刻只有一个写事务，
  扫描的多个工作线程各自持有一个批次写事务。

### 3.3 Scanning（扫描引擎）

- **分片**：卷根 + 每个一级子目录各一片，登记进 `shardPaths`；
  卷根遍历遇到这些目录不再下钻（否则同一目录被两遍计数）。
- **目录枚举**：`FindFirstFileExW` + `FindExInfoBasic`；不请求 8.3 短名。
- **写入**：工作线程各持一个 `FileBatchWriter`（单事务 + 预编译语句），
  缓冲 512 条刷一次；主线程负责分片登记的写入。
- **增量**：`dir_index` 保存目录 mtime 与子树文件数；`mtime` 一致即整棵跳过，
  跳过部分按上轮记录的文件数/字节数计入总量，因此统计不失真。
  分片根始终遍历一次（其直接子项就是分片集合），其余目录走跳过路径。
- **只读**：`DeleteFilesUnder` 删除的是数据库中的陈旧行，不触碰文件系统。
- **安全阀**：`MaxEntries` 上限；`CancellationToken` 支持中止；工作线程 `BelowNormal` 优先级。

### 3.4 Recognition（内容识别）

双通道判定 + 内容提取，详见 README 4.5。
额外设计：`file_types` 表把扩展名规则落库，规则变更可审计；
`dir_index`、`magic`、`mime` 等字段让“识别覆盖率”可被 SQL 直接统计（设置页与磁盘页展示）。

### 3.5 Cleanup（清理规则与一键清理）

- 默认规则 40 余条，模式形如 `*\AppData\Local\Temp\*`；
  `CleanupRules.ToLikePattern` 负责把通配符转成 SQL `LIKE`（`*`→`%`、`?`→`_`，并转义 `\`、`%`、`_`）。
  反斜杠双写是关键：库里的路径是 `C:\Users\...`，SQLite 的 LIKE 用 `\` 作转义符，
  不双写会出现“模式匹配不到任何文件”的静默失效。
- `BuildPlan` 只收录**安全级**条目，并用防护引擎重新判定一次（不信任库中旧风险值）。
- `Execute` 逐条走 `OperationExecutor.Recycle`，返回释放量、耗时与被拦截/失败计数。

### 3.6 Safety（误删防护）

- `PathTools`：规范化、卷根解析、通配符匹配、系统保留目录名判定。
- `ProtectionEngine`：`_protectedExact` / `_protectedPrefix` 前缀集合 + 用户白名单模式。
  临时目录是唯一的“受保护前缀例外”——否则用户永远无法清理自己的 `%TEMP%`。
- `OperationExecutor`：`CheckDeletable` 返回拦截原因（null 表示允许），
  删除/移动/重命名统一在此收口并写双份日志。
- `ShellFileOperations`：`IFileOperation` 定义（含 `IFileOperationProgressSink` 的托管实现），
  失败自动回退 `SHFileOperation` + `FOF_ALLOWUNDO`；回收站不可用时明确报错。

### 3.7 Resources（资源管家与调度器）

- `NativeMemory`：`GlobalMemoryStatusEx`、`NtQuerySystemInformation`、
  `EmptyWorkingSet`、`SetPriorityClass`、令牌提权检测与特权启用。
- `ResourceOptimizer`：快照、清理、报告。豁免规则：自身进程、前台窗口进程、系统关键进程名清单、
  用户白名单、工作集小于阈值的进程；仅处理当前会话。
- `CronExpression` / `IntervalSchedule` / `ResourceScheduler`：20 秒评估周期、5 分钟冷却、
  未触发时给出人类可读的原因（“未达内存阈值”“系统仍在使用中”），便于用户理解为何没执行。

### 3.8 Network（合规版网络优化）

- `ProbeService`：并发 6 路，DNS/TCP/HTTPS 三段计时；443 端口额外做一次 HEAD 往返
  （证书链问题不影响可达性判定）。系统代理信息**只读**：Internet Settings 注册表 + 环境变量 +
  `netsh winhttp show proxy`。
- `MirrorCatalog`：内置镜像清单、包管理器镜像命令文本、SSH over 443 建议配置、克隆命令向导。
- `GitConfigEngine`：`ConfigSnapshot`（git 全局配置 + `~/.ssh/config` + 代理环境变量）
  落盘到 `config\git-snapshots`；应用前必建快照；还原时对未设置的键执行 `unset`，
  不留残留；`ApplyProxy` 校验 scheme，拒绝非 http/https/socks5。

### 3.9 Homework（学习通）

`IHomeworkPlatformAdapter`：`IsConfigured` / `CapabilityDescription` / `SyncAsync`。
两个实现：`LocalImportAdapter`（离线，看板与提醒照常）与 `GenericJsonAdapter`
（端点与字段路径全部可配置）。同步结果用 `SyncResult` 明确区分
成功 / 失败 / 跳过（频率受控）/ 会话失效 / 降级，界面据此给出不同文案，绝不伪造数据。

### 3.10 Compliance（合规审计）

- 二进制审计：扫描程序目录内 `*.exe`/`*.dll`，用 Latin-1 解码后同时匹配 ASCII 与 UTF-16LE 关键字；
  排除审计工具自身（关键字清单就在其中）。
- 源码审计：扫描 `.cs` 文件，并对“危险注册表动作 + Internet Settings/hosts 目标”做组合规则判定。
- 正向声明：列出本程序允许的全部系统写入点，供人工核对。
- 关键字必须是完整 API 名或文件路径（早期用 "TDI"/"WFP" 这类短缩写会产生 `stdint` 之类的假阳性，
  审计工具自身的可信度同样重要）。

## 四、数据模型

```sql
files(id, path UNIQUE, parent, name, ext, kind, size, mtime, md5, risk,
      recognized, category, mime, summary, volume, subtree, magic, updated_at)
  -- idx: path(unique), parent, volume, (risk,recognized), size DESC, category
dir_index(path PK, mtime, child_count, total_size)   -- 增量扫描的目录指纹
file_types(ext PK, mime, magic, category)            -- 扩展名规则（可审计）
cleanup_rules(id, pattern UNIQUE, category, risk, enabled, note)
course(id PK, name, teacher, term, source, sync_time)
homework(id PK, course_id, title, deadline, platform_status, platform_state,
         submitted_at, local_done, source, sync_time)
sync_log(id, sync_time, result, error_msg, duration_ms, course_count, homework_count, adapter)
reminder_log(id, homework_id, threshold_h, deadline, sent_at) UNIQUE(homework_id,threshold_h,deadline)
settings(key PK, value)
operation_log(id, ts, op, src, dst, result, detail)
scan_history(id, mode, started_at, finished_at, files, dirs, bytes, skipped, denied, seconds)
```

设计要点：

- `files` 按 `parent` 建索引，树状图展开是一次 `WHERE parent = ?` 查询，天然满足 ≤200ms。
- `md5` 默认不计算，仅在重复文件分析时按需计算（避免全量哈希拖慢扫描）。
- `reminder_log` 的唯一索引保证“同一作业同一档位同一截止时间只提醒一次”，
  使“提醒到达率 100%”具备可验证的持久化依据。
- `updated_at` + 全量扫描后的 `DeleteFilesUnder` 解决“幽灵条目”。

## 五、线程与并发模型

| 场景 | 线程模型 |
| --- | --- |
| 扫描 | 主线程建分片；N 个工作线程（默认 CPU 核数，≤8）消费 `BlockingCollection` 分片队列；1 个进度线程每 400ms 发布快照 |
| 内容识别 | `Parallel.ForEach`，度 = min(CPU, 8)，分批落库 |
| 数据库写 | 进程内单写事务锁；工作线程各自持有批次写事务 |
| 资源调度 | 1 个后台线程，20 秒评估一次 |
| 学习通同步 | `SemaphoreSlim` 保证不并发；自动同步线程按配置间隔轮询 |
| UI | WPF Dispatcher；所有耗时操作 `Task.Run` + `ConfigureAwait(true)` 回 UI 线程；进度事件 250ms 节流 |

## 六、权限与提权

- `app.manifest` 固定 `requestedExecutionLevel = asInvoker`，声明 `longPathAware` 与 UTF-8 代码页。
- 扫描、查看、删除（自己的文件）、工作集压缩、优先级调整均**不需要管理员**。
- 仅“Standby 待机列表清理”需要管理员：非提权时明确跳过并在报告中说明，不做静默失败。
- 提权后调用 `AdjustTokenPrivileges` 启用 `SeProfileSingleProcessPrivilege` /
  `SeIncreaseQuotaPrivilege`，失败不影响主流程。
- **主进程永不常驻高权限**：没有“提权后执行任意命令”的通道，
  删除等操作由同一进程内的白名单逻辑约束。

## 七、合规边界（功能一红线）

**代码层面没有实现，且由自检回归**：

| 红线 | 本项目的做法 |
| --- | --- |
| 不修改 hosts | 无任何 hosts 路径的写入代码；二进制扫描确认无 `drivers\etc\hosts` |
| 不内置/自动启用代理或 VPN | 无 `WinHttpSetDefaultProxyConfiguration`、无 RAS/Wintun/WireGuard/TAP 调用 |
| 不安装网络驱动或过滤规则 | 无 `FwpmEngineOpen`/`FwpmFilterAdd`、无 `netsh advfirewall` |
| 不改写系统代理设置 | 只**读取** Internet Settings 与 `netsh winhttp show proxy` 用于展示 |
| 不针对受限资源自动访问 | 只有被动连通性测量；测不通只如实展示并提示走官方渠道 |

功能可以整体停用（「① 网络访问优化」页的“启用网络优化功能”开关），关闭后不进行任何测速或写入。

所有配置写入都可一键还原：快照包含 git 全局配置、`~/.ssh/config` 与代理环境变量，
还原时逐项恢复、对快照中不存在的键执行 `unset`。

## 八、如实说明的技术边界

1. 工作集压缩属短期整理，系统会按需重新调入页面；不结束进程的前提下内存回收存在客观上限。
2. 待机列表清理的收益与系统负载场景相关，且需要管理员权限。
3. 学习通私有接口需实机抓包确定端点，本工具只提供可插拔接入点与本地/导入降级模式。
4. 扫描吞吐受磁盘类型、文件粒度与杀软实时扫描影响；程序只保证“只读、可中止、可增量”。
5. 自包含发布需联网获取运行时包，离线环境只能产出框架依赖版本。
